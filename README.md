# WebsiteMonitor — сервис мониторинга доступности веб-сайтов и API

Учебный проект: приложение отслеживает доступность указанных пользователем
веб-сайтов и REST API endpoints, сохраняет историю проверок и время отклика,
регистрирует инциденты (сбои) и показывает статистику с графиками.

Поставляется в двух самостоятельных версиях с одинаковым функционалом общей
бизнес-логикой и одной базой данных:

| Версия      | Интерфейс                       | Запуск                              |
|-------------|----------------------------------|-------------------------------------|
| Веб-версия  | браузер (локальный веб-сервер)  | `WebsiteMonitorWeb.exe`             |
| Десктоп     | нативное GUI (PySide6)           | `WebsiteMonitorDesktop.exe`         |

## Возможности

- Главная панель со сводкой: сайты, доступность, среднее время отклика, сбои,
  последние события.
- Управление сайтами: добавление, изменение названия/URL/интервала, удаление,
  включение–отключение мониторинга, проверка вручную.
- Автоматический мониторинг в фоновых потоках (интерфейс не зависает):
  HTTP GET, замер времени отклика, поддержка редиректов, обработка DNS-ошибок,
  ошибок соединения, таймаутов и SSL.
- История проверок каждого сайта с фильтрами по сайту и периоду и очисткой.
- История сбоев: инциденты открываются при первом сбое и закрываются после
  восстановления, длительность считается автоматически.
- Статистика и графики (время отклика и доступность) за 24 часа, 7 и 30 дней.
- Защита от SSRF: по умолчанию запрещены localhost, приватные, link-local и
  служебные адреса; адрес повторно проверяется после DNS-разрешения и на каждом
  шаге редиректа. Для демонстрации на локальном сервере можно включить
  разрешение приватных адресов переменной окружения
  `WEBSITE_MONITOR_ALLOW_PRIVATE=1`.
- SQLite + SQLAlchemy, таблицы создаются автоматически при первом запуске.

## Технологии

Python 3.12 · Flask · PySide6 · SQLAlchemy · SQLite · Requests ·
Chart.js (в веб-версии) · PyInstaller (сборка EXE).

## Требования

- Для запуска собранных EXE: Windows, установленный Python не нужен.
- Для запуска из исходного кода: Python 3.12 и зависимости из
  `requirements.txt` (веб-версия) и `PySide6` (десктоп-версия).
- Для сборки EXE: Python 3.12 + `requirements-dev.txt` (PyInstaller) на Windows.

## Запуск из исходного кода

```bash
# 1) окружение
python -m venv .venv
# Windows:
.venv\Scripts\pip install -r requirements.txt
# Linux/macOS:
.venv/bin/pip install -r requirements.txt

# 2) веб-версия (откроет браузер на http://127.0.0.1:<порт>/)
# Windows:
.venv\Scripts\python web_main.py
# Linux/macOS:
.venv/bin/python web_main.py

# 3) десктопная версия
.venv\Scripts\python desktop_main.py   # Windows
.venv/bin/python desktop_main.py       # Linux/macOS
```

## Сборка EXE (два самостоятельных приложения)

На Windows, из корня проекта:

```bat
build.bat
```

Результат (сборка в режиме onedir):

```
build/release/WebsiteMonitorWeb/WebsiteMonitorWeb.exe
build/release/WebsiteMonitorDesktop/WebsiteMonitorDesktop.exe
```

Каждое приложение автономно — Python и библиотеки не нужны. Обе версии
используют **один и тот же файл базы данных** (см. ниже), поэтому одновременно
могут работать c общими данными.

Примечание: PyInstaller не умеет кросс-компилировать — `.exe` собираются на
Windows. Скрипт `build.sh` выполняет аналогичную сборку на Linux/macOS
(с теми же параметрами) и удобен для проверки процесса сборки.

## Расположение базы данных

Файл базы данных лежит в постоянной пользовательской директории, а не рядом с
EXE и не во временной папке PyInstaller:

| ОС       | Путь                                           |
|----------|------------------------------------------------|
| Windows  | `%LOCALAPPDATA%\WebsiteMonitor\data\monitor.db` |
| Linux    | `~/.local/share/WebsiteMonitor/data/monitor.db` |

Переменная окружения `WEBSITE_MONITOR_DB_PATH` (абсолютный путь к файлу)
позволяет переопределить расположение (используется в тестах).

## Тестирование

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests/ -q
```

Тесты используют локальный управляемый HTTP-сервер и не зависят от интернета.
Сквозной сценарий: `tests/e2e.sh`.
